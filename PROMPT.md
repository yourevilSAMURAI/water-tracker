### Промпт для создания Water Tracker (v1.0)

Этот файл содержит детальный промпт, с помощью которого можно сгенерировать аналогичный проект.

## Основной Промпт:

> **Роль:** Ты — Senior Frontend-разработчик и эксперт по UI/UX дизайну.
> 
> **Задача:** Напиши код для одностраничного веб-приложения (SPA) — трекера воды. Используй чистый HTML, CSS и Vanilla JavaScript. Код должен быть разделен на три файла: `index.html`, `style.css` и `script.js`.
> 
> **Общий стиль (Дизайн):**
> *   Минимализм. Светлая тема — "Cold Wave" (пастельно-голубой фон, белые карточки, черные контуры, шрифт Montserrat).
> *   Темная тема — "Dark Wave" (глубокий черный фон, темно-серые карточки, акцентный красный цвет).
> *   Использовать CSS-переменные (`:root` и `[data-theme="dark"]`) для переключения тем.
> 
> **Функционал:**
> 1.  **Главный экран:** Круговой SVG-прогресс-бар, показывающий выпитое количество относительно цели (по умолчанию 2000 мл).
> 2.  **Добавление воды:** Кнопки быстрого выбора (+200, +250, +500 мл) и поле для ввода своего объёма (с валидацией от 1 до 3000).
> 3.  **Отмена:** Кнопка «Отменить шаг», которая удаляет последнюю запись за выбранный день.
> 4.  **Календарь (в правой панели):** Сетка дней текущего месяца. Каждый день имеет мини-иконку стакана, заполненного пропорционально выпитой воде. Будущие дни заблокированы.
> 5.  **Журнал (в правой панели):** При клике на день в календаре открывается список записей с точным временем (например, "14:30 — 250 мл").
> 6.  **Левая панель:** Текст «О нормах» (о пользе и вреде воды, расчет нормы).
> 7.  **Предупреждение:** Если выпить больше 115% от цели, показать модальное окно с предупреждением (показывать один раз в день).
> 8.  **Тема:** Кнопка переключения тем.
> 
> **Дополнительные требования:**
> *   Данные сохранять в `localStorage` (история по дням).
> *   Использовать безопасный `JSON.parse` с `try/catch` на случай повреждения данных.
> *   Реализовать проверку наступления нового дня (чтобы приложение не писало вчерашние данные в сегодняшние).
> *   Добавить поддержку клавиш `Enter` (для добавления) и `Escape` (для закрытия панелей и модалок).
> *   Адаптивность: на мобильных устройствах панели должны быть не шире экрана (`max-width: calc(100vw - 40px)`).




### Полный и структурированный `PROMPT.md для v2.0 - Full-Stack Telegram Mini App`

Этот промпт теперь полностью описывает архитектуру v2.0 (клиент-сервер), чтобы нейросеть не писала код для `localStorage`.
Этот файл содержит детальный промпт, с помощью которого можно сгенерировать аналогичный Full-stack проект (Node.js + Express + Turso DB + Vanilla JS).

## Основной Промпт для нейросети:

> **Роль:** Ты — Senior Full-Stack разработчик и эксперт по кибербезопасности.
> 
> **Задача:** Напиши код для Telegram Mini App — трекера воды. Проект должен состоять из Frontend (HTML, CSS, Vanilla JS) и Backend (Node.js, Express), с подключением к облачной базе данных Turso (SQLite).
> 
> **1. Архитектура и Безопасность (Критически важно!):**
> *   **Авторизация:** Никогда не доверяй `userId`, приходящему от клиента. Реализуй Express-мидлвар (`verifyTelegramData`), который берет заголовок `x-telegram-init-data`, проверяет его HMAC-SHA256 подпись с помощью `TELEGRAM_BOT_TOKEN` (используя модуль `crypto`) и извлекает реальный `user.id`.
> *   **База данных:** Используй библиотеку `@libsql/client`. Создай таблицы `users` (id, telegram_id, daily_goal) и `water_logs` (id, user_id, amount, date, time). Внешний ключ `user_id` должен иметь `ON DELETE CASCADE`. Используй `INSERT OR IGNORE` при создании юзера для защиты от Race Condition.
> *   **Переменные окружения:** Все секреты (URL базы, токены) должны читаться из `process.env`.
> 
> **2. Функционал Frontend:**
> *   **Интеграция с Telegram:** Вызови `tg.ready()` и `tg.expand()`. Автоматически передавай `tg.initData` в заголовках при каждом `fetch` запросе к серверу.
> *   **Главный экран:** Круговой SVG-прогресс-бар (цель 2000 мл).
> *   **Добавление воды (с защитой от спама):** Кнопки +200, +250, +500 мл и кастомный ввод. Внедри флаг `isSending` (замок), чтобы предотвратить отправку дублей. На время запроса делай кнопки полупрозрачными.
> *   **Календарь и Журнал:** Сетка дней месяца с мини-стаканами прогресса. При клике на день — список записей.
> *   **Сброс:** Кнопка "Сбросить все" должна отправлять `DELETE` запрос на сервер (очистка в БД).
> *   **Дизайн:** Светлая тема "Cold Wave" и темная "Dark Wave" через CSS-переменные. Адаптивная верстка.
> 
> **3. Функционал Backend (API):**
> *   `POST /api/water`: Добавление записи.
> *   `GET /api/water`: Получение истории *только за последние 60 дней* (SQL запрос с `date >= date('now', '-60 days')`) для оптимизации.
> *   `DELETE /api/water/:id`: Удаление записи (проверка, что запись принадлежит текущему юзеру).
> *   `DELETE /api/water/all`: Очистка истории текущего пользователя.
> 
> **Требования к коду:**
> *   Используй асинхронные функции (`async/await`) и обработку ошибок `try/catch`.
> *   Код должен быть разбит на файлы: `server.js`, `database.js`, `script.js`, `index.html`, `style.css`.
> *   Соблюдай чистоту кода (DRY, KISS).
